# إعداد MongoDB Atlas لتطبيق سجل بوابة المجبل

> **تنبيه على الاسم:** الخدمة اسمها **MongoDB Atlas** وموقعها
> <https://www.mongodb.com/atlas>. لا علاقة لها بشركة **Atlassian**
> (صاحبة Jira و Confluence) — البحث بالاسم الخطأ سيضيّع وقتك ووقت قسم الـ IT.

---

## قبل أن تبدأ — ما يتغيّر بانتقالك للسحابة

| | MongoDB محلية على السيرفر | MongoDB Atlas |
|---|---|---|
| الإنترنت | غير مطلوب إطلاقًا | **مطلوب دائمًا** |
| إن انقطع الإنترنت | التطبيق يعمل عادي | **البوابة تتوقّف عن التسجيل** |
| زمن كل عملية | أقل من مللي ثانية | 50–300 مللي ثانية |
| بيانات الشركة | داخل مبنى الشركة | على خوادم مزوّد خارجي |
| النسخ الاحتياطي | مسؤوليتك | تلقائي في الخطط المدفوعة |
| الصيانة والتحديث | مسؤوليتك | على المزوّد |

**النقطة الأهم:** ربط بوابة المجبل بقاعدة سحابية يعني أن انقطاع الإنترنت
يوقف تسجيل الشاحنات، والشاحنات لا تنتظر. هذا ليس سببًا لرفض Atlas، لكنه سبب
وجيه لإضافة الحفظ المحلي المؤقّت في التطبيق (طابور يُرفع عند عودة الاتصال)،
وهو غير مبنيّ بعد.

**قبل المتابعة تأكّد من:** موافقة الشركة على خروج بيانات التشغيل إلى مزوّد
خارجي — كثير من الشركات لديها سياسة صريحة في هذا.

---

## خطوات الإعداد

### 1. إنشاء الحساب والعنقود

1. افتح <https://www.mongodb.com/atlas> واضغط **Try Free**
2. بعد التسجيل: **Build a Database**
3. اختر الخطة:
   - **M0 (مجاني)** — 512 ميغابايت. كافية تمامًا لحجم بياناتك (بضعة آلاف
     سجل سنويًا). لكنها **بلا نسخ احتياطي تلقائي** وقد تتوقّف مؤقتًا عند
     عدم الاستخدام. مناسبة للتجربة لا للتشغيل الفعلي.
   - **M10 فما فوق** — مدفوعة، فيها نسخ احتياطي تلقائي. هذه المناسبة للتشغيل الحقيقي.
4. اختر **المنطقة الأقرب جغرافيًا** لموقع الشركة — كل كيلومتر إضافي يزيد
   زمن الاستجابة على كل عملية تسجيل.

### 2. إنشاء مستخدم قاعدة البيانات

**Database Access** → **Add New Database User**

- طريقة المصادقة: **Password**
- اسم المستخدم: `gatelog_app`
- كلمة المرور: اضغط **Autogenerate Secure Password** واحفظها فورًا
- الصلاحية: **Read and write to any database** — أو الأدق:
  **Specific Privileges** → `readWrite` على قاعدة `gate_log` فقط

> **مهم:** إن أنشأت كلمة المرور بنفسك وكانت تحتوي `@` أو `/` أو `:` أو `?`
> أو `#`، فيجب ترميزها داخل الرابط: `@` تصبح `%40`، و`/` تصبح `%2F`،
> و`:` تصبح `%3A`. أسهل حل: استخدم كلمة مرور مولّدة تلقائيًا بلا رموز.

### 3. السماح لعنوان الشركة بالوصول

**Network Access** → **Add IP Address**

اعرف عنوان IP العام لشبكة الشركة بتنفيذ هذا **على السيرفر نفسه**:

```bash
curl https://api.ipify.org
```

أضف العنوان مع وصف مثل `مقر الشركة`.

> **⚠ نقطة تُنسى كثيرًا:** إن كان اشتراك إنترنت الشركة بعنوان IP **متغيّر**
> (وهو الشائع في الاشتراكات غير المخصّصة للأعمال)، فسيتوقّف التطبيق عن
> العمل فجأة كلما غيّر المزوّد العنوان — وسيبدو العطل غامضًا تمامًا.
> **الحل الصحيح:** اطلب من مزوّد الخدمة عنوان IP ثابتًا.
>
> **لا تستخدم** `0.0.0.0/0` (السماح للجميع) كحل سريع — يجعل قاعدة بياناتك
> مكشوفة للإنترنت كله، ولا يحميها إلا كلمة المرور.

### 4. الحصول على رابط الاتصال

**Database** → **Connect** → **Drivers** → اختر **Node.js**

انسخ الرابط، وسيكون بهذا الشكل:

```
mongodb+srv://gatelog_app:<db_password>@gatelog.ab1cd.mongodb.net/?retryWrites=true&w=majority
```

استبدل `<db_password>` بكلمة المرور الفعلية.

### 5. وضع الرابط في التطبيق

أنشئ ملف `gatelog.config.json` في مجلد التطبيق:

```json
{
  "driver": "mongo",
  "mongoUri": "mongodb+srv://gatelog_app:كلمة-المرور@gatelog.ab1cd.mongodb.net/?retryWrites=true&w=majority",
  "mongoDb": "gate_log",
  "port": 8787
}
```

ثم **قيّد صلاحيات الملف** — فهو يحتوي كلمة المرور:

```powershell
icacls gatelog.config.json /inheritance:r /grant:r "SYSTEM:(R)" "Administrators:(F)"
```

> لماذا ملف لا متغيّر بيئة أو سطر أوامر؟ لأن الرابط يحتوي كلمة المرور:
> في سطر الأوامر يظهر لأي مستخدم على السيرفر عبر Task Manager، وفي متغيّر
> بيئة على مستوى الجهاز يصبح مقروءًا لكل الحسابات.

### 6. التشغيل والتحقق

```bash
node server.js
```

يجب أن يظهر سطر «قاعدة البيانات MongoDB → mongodb+srv://gatelog_app:****@…».
كلمة المرور تظهر مُقنّعة دائمًا في السجلات.

للتأكد من وصول البيانات فعلًا إلى Atlas:

```bash
node test/verify-mongo.js
```

ثم افتح **Database** → **Browse Collections** في لوحة Atlas — يجب أن ترى
مجموعات `vehicles` و `entries` و `audit` وغيرها بالبيانات نفسها.

## إن فشل الاتصال

التطبيق يشخّص العطل ويطبع الخطوة المطلوبة. أشهر ثلاثة أعطال:

| الرسالة | السبب | الحل |
|---|---|---|
| تعذّر ترجمة اسم نطاق Atlas | لا إنترنت، أو جدار الحماية يحجب استعلامات DNS من نوع SRV، أو المنفذ 27017 الصادر محجوب | افتح المنفذ 27017 **الصادر** واسمح باستعلامات SRV |
| عنوان IP غير مسموح به | لم يُضَف عنوان الشركة، أو تغيّر | أضفه في Network Access |
| اسم المستخدم أو كلمة المرور غير صحيحة | خطأ في النسخ، أو رمز غير مُرمَّز في كلمة المرور | راجع Database Access، ورمّز الرموز الخاصة |

## متطلبات الشبكة — لقسم الـ IT

| المتطلب | التفصيل |
|---|---|
| منفذ صادر | **TCP 27017** من السيرفر إلى الإنترنت |
| DNS | السماح باستعلامات **SRV** و **TXT** لنطاق `*.mongodb.net` |
| عنوان IP عام ثابت | مطلوب لقائمة السماح في Atlas |
| التشفير | Atlas يفرض TLS تلقائيًا — بيانات القاعدة مشفّرة أثناء النقل |

انتبه: تشفير TLS هنا يحمي المسار بين **السيرفر و Atlas** فقط. المسار بين
**جهاز البوابة والسيرفر** ما زال HTTP غير مشفّر — إن كانت السياسة تفرض
التشفير الكامل فستحتاج IIS كوسيط عكسي بشهادة داخلية.

## النسخ الاحتياطي

- **M0 المجانية:** لا نسخ تلقائي. اعتمد على لقطات JSON التي يكتبها التطبيق
  في `data/backups` كل 24 ساعة، وانسخها إلى مكان آمن دوريًا.
- **M10 فأعلى:** نسخ احتياطي مستمر من Atlas — فعّله من
  **Backup** في لوحة التحكم.

في الحالتين يبقى تصدير CSV من داخل التطبيق متاحًا كنسخة مقروءة بشريًا.

## العودة إلى قاعدة محلية

إن قرّرت لاحقًا أن الاعتماد على الإنترنت مخاطرة أكبر من فائدة السحابة،
العودة لا تحتاج أي تعديل على الكود — فقط غيّر `mongoUri` في ملف الإعدادات
إلى `mongodb://127.0.0.1:27017`، وانقل البيانات:

```bash
mongodump --uri "mongodb+srv://gatelog_app:كلمة-المرور@gatelog.ab1cd.mongodb.net" --db gate_log --out backup
```

```bash
mongorestore --uri "mongodb://127.0.0.1:27017" --db gate_log backup/gate_log
```
